Source Error Issue 1: app.py - Attribute Access on None
src/parkbot/gui/app.py:200-202
The type checker reports that match_count, reaction_count, and fail_count are accessed on a potentially None object (self.bot has type None | RPABotCore).
Root Cause: The App class initializes self.bot = None and only creates the bot instance when the user clicks "启动运行". However, the status update method tries to access bot attributes without checking if bot exists, which could cause runtime errors if status is updated before bot initialization.

❌ Current (Unsafe)

f"📊 本次运行统计 - 匹配: {self.bot.match_count} | "
f"点赞: {self.bot.reaction_count} | "
f"失败: {self.bot.fail_count} | "

✅ Fixed (Safe)

bot_stats = (
    f"匹配: {self.bot.match_count} | "
    f"点赞: {self.bot.reaction_count} | "
    f"失败: {self.bot.fail_count}"
    if self.bot else "机器人未启动"
)
f"📊 本次运行统计 - {bot_stats} | "
Note: Tests currently pass because the code path with None bot may not be exercised, but this is a legitimate bug that could cause AttributeError at runtime.

Source Error Issue 2: font_config.py - tkinter Internal API Access
src/parkbot/gui/font_config.py:27, 167
The code accesses tk._default_root which is a tkinter internal attribute. The type checker reports "Module tkinter has no member _default_root".
Root Cause: The code tries to access the default root window to configure fonts globally. While this works at runtime, it uses tkinter's internal API (prefixed with underscore) which is not part of the public interface and may break in future Python versions.

❌ Current (Internal API)

@staticmethod
def initialize_fonts():
    root = tk._default_root
    if root is None:
        return

✅ Fixed (Using CustomTkinter)

@staticmethod
def initialize_fonts():
    # Get the current CTk instance or return if not available
    try:
        import customtkinter as ctk
        root = ctk.CTk()
        # Configure fonts on the root window
        # ... rest of font configuration
    except Exception:
        return
Alternative Approach: Since this is GUI code that runs after the app starts, we could also store a reference to the root window when the App is created and pass it to FontConfig.

Test Warning Issue 4: test_models.py - Type Safety in Comparisons
tests/chat/test_models.py:100, 118
Type checker reports that comparison operations between datetime | None and datetime are not supported because None doesn't support comparison operators.
Analysis: While the test logic is correct (reacted_at is guaranteed to be set before the assertion), the type checker cannot infer this. The fix is to add an explicit assertion to narrow the type.

❌ Current (Type Unsafe)

# Line 100

# Line 118

✅ Fixed (Type Safe)

# Line 100

assert before <= msg.reacted_at <= after

# Line 118

assert first_reacted_at is not None
assert msg.reacted_at > first_reacted_at

⚠️ Important: TY-Specific Syntax

TY uses # ty: ignore[<rule>] syntax (not # type: ignore like mypy). According to TY documentation, we must use the TY-specific suppression format.

The 7 Lines to Skip with Correct TY Syntax:

# File Line TY Rule Name TY Ignore Comment
1 tests/chat/test_models.py 100 unsupported-operator # ty: ignore[unsupported-operator]
2 tests/chat/test_models.py 118 unsupported-operator # ty: ignore[unsupported-operator]
3 tests/chat/test_models.py 142 deprecated # ty: ignore[deprecated]
4 tests/chat/test_models.py 152 deprecated # ty: ignore[deprecated]
5 tests/core/test_message_id_validation.py 27 invalid-argument-type # ty: ignore[invalid-argument-type]
6 tests/core/test_rpa_bot.py 175 invalid-assignment # ty: ignore[invalid-assignment]
7 tests/gui/test_app.py 296 unresolved-attribute # ty: ignore[unresolved-attribute]

❌ WRONG Syntax (Don't Use)

# These are INCORRECT for TY:
assert before <= msg.reacted_at <= after  # type: ignore[operator]
assert RPABotCore.is_temporary_message_id(None) is True  # type: ignore[arg-type]

The # type: ignore syntax is for mypy, not TY!

✅ CORRECT TY Syntax (Use This)

# TY uses # ty: ignore[<rule>] syntax:
assert before <= msg.reacted_at <= after  # ty: ignore[unsupported-operator]
assert RPABotCore.is_temporary_message_id(None) is True  # ty: ignore[invalid-argument-type]

Reference: https://docs.astral.sh/ty/suppression/

❌ Wrong Approach (Global)

# In pyproject.toml - DON'T DO THIS
[tool.ty.rules]
unresolved-attribute = "ignore"  # Too broad!
invalid-argument-type = "ignore"  # Affects all files!

✅ Correct Approach (Targeted)

# In test files - ONLY these 7 lines
assert before <= msg.reacted_at <= after
# ty: ignore[unsupported-operator]

assert RPABotCore.is_temporary_message_id(None) is True
# ty: ignore[invalid-argument-type]

✓ Why This Approach is Better:

  • Only affects the 7 specific problematic lines
  • Source code files still get full type checking
  • Other test file lines still get checked
  • Explicit documentation of why each line is skipped
  • Easy to remove when ty improves
